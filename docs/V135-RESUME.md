# V135 恢复记录

## 实机结论

V135 是继续工作的设备基线。用户确认完整应用可用、设置 About 可打开、触摸和 GPU 正常。壁纸仍为黑色。V136 曾破坏触摸/GPU；恢复 V135 后正常。V137 与 V138 壁纸尝试无效，因此不把壁纸实验带入稳定基线，也不再自动进行相关实机测试。用户已准备返回原系统，当前平板模式未知。

应用 Waiting 的修复来自 Data 中完整应用原有的 BundleMetadata.plist 及对应安装类型扩展属性。安装类型值为 10，扩展属性是 8 字节小端整数。修复保留了 28 个完整应用和可执行文件，并移走最多两个旧 LaunchServices 缓存。它是 Data 初始化/恢复步骤，不是 V135 内核自身的功能，也不能靠重放旧物理页增量复制到新的 Data。

V135 的显示改动只回答 21H461 GOP backend timing-enable 查询为 false，并保留原先取消/超时路径。等长指令替换和版本标记都在公开源码/补丁中。它没有证明显示硬件具备原生 timing-enable 控制，也没有证明壁纸问题由该路径导致。

## 构建证据

- 实机确认的 V135 boot：33,490,944 字节，SHA-256 1a5265f9fcbb19314510310c0e341c98c88f96b58ab9a99aeecf39c9e0fb3174。
- 内核：52,936,704 字节，SHA-256 342a0be94069c26d0d46a1e1fac03e4a396d89ea09bbc5c5acc5b5336ee10f23。
- 完整 XNU 源码编译没有完成。V135 是从保留 V131 父 kernel.macho 的固定地址作 24 字节等长指令派生，并更新一个版本字符串；绝不能将它记为 full XNU source build。
- 使用归档 V135 固件和新编译 BootShim 的 quick-pack，含完整私有工具哈希校验复现了实机镜像完整 SHA-256，约 13.5 秒。
- 独立干净目录的 EDK2 固件构建成功；使用已安装原生工具约 146.89 秒，使用私有 capsule 内复制工具约 150.2 秒，均生成 32 MiB 固件和镜像。重编固件哈希不同于实机 V135 固件；capsule 工具产物 SHA-256 为 aabffcccd08abd961d018a00400fd9f7e639cefefe21d290f3fa7e6210710556，没有实机验证。它只证明固件源码入口可用；用于准确延续已验证状态应选 quick-pack。

## 保留内容

维护者的私有输入包位于被忽略的本机目录 research/v135-resume-private-2026-11-09/。其中有构建源、V131 父内核、准确 V135 固件、设备 DTB、原始 boot 恢复备份、V135 实机 boot、输入哈希清单，以及单独分卷压缩的 V135 Data 和 OS/SystemOS 根输入。稀疏分卷保留逻辑长度、数据 extent 与每块压缩前/后 SHA-256。该目录及所有 Apple 输入、数据、密钥、设备备份都不能推送到公共 GitHub。

该本机归档是快速续接材料，不等于公开仓库独立获得完整系统输入。全新 Mac/工作区需要另行准备匹配的 21H461 系统、固件、签名/ABI输入和工具链；不能从公开仓库下载 Apple 系统，也不能把旧 Data/恢复镜像刷到另一台设备。

## 接续顺序

1. 克隆公开仓库，阅读本记录和 BUILDING.md。
2. 在原维护 Mac 使用私有输入目录，先运行 quick-pack；生成镜像应匹配上述 V135 SHA。
3. 需要重新编译 EDK2 固件时运行正常构建模式。它会生成未实机验证的新候选，不替代准确 V135 基线。
4. 新 Data 需要先装入完整 21H461 原生应用包和其 metadata；在离线挂载卷用 prepare_apps_v135.py 生成计划、人工检查后再执行 apply。完整应用内容必须存在，脚本不会伪造应用或下载 Apple 文件。
5. 壁纸调试与 GPU 调优按用户要求暂停。恢复工作时从 V135 保存点提出新的具体目标。

公开仓库构建器只创建本地文件，不连接设备、不写分区、不选择启动项。历史硬件 runner 和单次 ledger 均不可重放。
