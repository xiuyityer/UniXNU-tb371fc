# 实机状态与里程碑

最后更新：2026-11-09。当前保存的稳定工作基准是 V135，系统目标为 iPadOS 17.7.11 / 21H461。

## 当前确认

- V135：用户报告应用 Waiting 修复生效，设置 About 可打开，触摸与 GPU 正常。
- 壁纸：V135–V138 的显示/图片导入尝试仍为黑屏。用户已决定暂停平板修复，返回原系统；当前物理模式未知，本记录不宣称已经刷回。
- V129 用户曾报告滑动较 V128 约快 5–10 FPS；这是主观叠加显示比较，不是仪器基准。GPU 调优暂停。
- 电池/充电状态与音量键仍未解决。

## 构建状态

- V135 用户确认镜像：boot 镜像 33,490,944 字节，SHA-256 1a5265f9fcbb19314510310c0e341c98c88f96b58ab9a99aeecf39c9e0fb3174。
- V135 内核 52,936,704 字节，SHA-256 342a0be94069c26d0d46a1e1fac03e4a396d89ea09bbc5c5acc5b5336ee10f23。它由保留父内核作等长定点指令派生；不是一次完整 XNU 源码构建。
- 新增公开脚本可从私有输入目录重新编译 EDK2 固件、BootShim 并打包。私有 capsule 工具链在空输出目录构建成功；约 150 秒，产物不是实机验证镜像。
- quick-pack 使用归档 V135 固件、重编 BootShim 和匹配 Android boot 工具；独立产物与实机确认 V135 镜像 SHA 完全一致，约 13.5 秒。
- 完整 XNU 构建仍需从原生上游工程整理所有目标系统生成头文件、ABI 和源构建步骤，当前没有宣称完成。

## 后续接手

1. 从公开仓库开始，先阅读 docs/V135-RESUME.md 和 docs/BUILDING.md。
2. 需要准确恢复 V135 时用私有输入目录和 quick-pack；要重新编译固件则用正常模式。两种构建均不访问设备。
3. 从零创建 21H461 Data 时，完整系统应用包和原生安装 metadata 必须作为初始输入。用 prepare_apps_v135.py 先生成只读计划，再在离线 Data 挂载目录运行 apply；不要重放旧物理页增量或硬件 ledger。
4. 新一轮 XNU 修改以 V135 已验证基准开始。壁纸/GPU 问题暂停，直到用户另行指定目标。
